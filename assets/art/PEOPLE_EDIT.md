# NPC source for Blender editing

Open `people-edit-source.blend` in Blender. The active `PeopleEdit` scene contains all 13 current near-detail characters, with one collection per archetype. Mesh parts and transform pivots retain names from `src/art/people.ts`; each figure is spaced on a grid only for editing. The driver is included alongside 12 passengers.

This is an editable **static stand-pose export** of the current runtime meshes and materials. The game still builds characters from `src/art/people.ts`; changes to the `.blend` do not appear in the game until the edited models are exported and integrated in a later pass. Pose logic, timing, and collision are not encoded as Blender actions or armatures in this file.

`people-edit-source.glb` is the import snapshot used to make the `.blend`. `export-people-to-gltf.mjs` can regenerate that snapshot from the TypeScript source, but regeneration replaces the snapshot; keep your edited `.blend` separate from the generated source.

The owner's edited duplicate `driver.adjusted` remains in `people-edit-source.blend`. The semi-chibi proportion pass is in **`people-polished.blend`**, active scene `PeoplePolished`. Its driver is an independent mesh copy of the owner's `driver.adjusted`, rather than a regenerated approximation. The other 12 editable characters come from `people-proportions-pass.glb`. `driver-adjusted-delivery.glb` is the standalone export of the copied driver. The `PeopleEdit` scene in the polished file also preserves the saved reference. The source file and its `.blend1` backup are not overwritten. `render-people-compare.py` renders the owner's adjusted driver beside the delivered copy; `build-people-polish-blend.py` rebuilds the packaged file and GLB. The `people.html` art page loads this actual Blender mesh for the driver and moves its edit pivots for pose previews. The 12 NPCs, vehicle-mounted art and game renderer still build from `src/art/people.ts`. The exported GLB has no baked Blender actions/armature, and no gameplay integration is claimed.
